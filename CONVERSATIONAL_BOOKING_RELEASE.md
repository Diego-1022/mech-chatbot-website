# Conversational booking

Customers can state a desired check-in date/time in chat, supply missing details conversationally and receive a pre-filled review card. The helper reads live availability through the workshop backend. It never reserves a slot during conversation; only the existing explicit Confirm booking action saves it and returns a real reference/private management link. Conflicts are checked again at save; existing unique-slot and idempotent retry rules remain.

Supported English/Chinese patterns include ISO dates, named English months, Chinese month/day, today/tomorrow/day-after-tomorrow, weekdays, am/pm, 24-hour times and Chinese hour expressions. Dates use Sydney time. Numeric slash dates and ambiguous short hours are not guessed; use a full date and clear time. Weekdays mean the next occurrence; omitted years use the current Sydney year. Unsupported expressions are clarified, not passed off as booked. This bounded deterministic workflow uses the existing API and no extra model/provider or AI budget. It does not grant the language model private-record access or arbitrary write tools.

The draft retains an explicitly provided vehicle, service, date and time, and reuses the signed-in customer's name/email unless corrected. Contact fields support labelled replies (name:, email:, phone:, vehicle:, notes:). Validated details go directly to the booking helper, never into AI chat history or saved account conversation rows. Drafts are temporary in the current browser session; a page reload clears them. Prior English symptom messages may populate notes, which remain editable on review. Booking field character/format policy remains unchanged. Selected photos during booking appear on the review and upload through the existing private booking-photo flow after confirmation; consultation images are not silently converted into booking attachments.

Account changes reset draft state and the final create request checks the expected account. Urgent symptoms override ordinary intake; closed/past/full slots cannot reach ready state. Users can return to chat or edit the confirmation form. New enquiries can be reset without clearing saved account history. Existing cancellation/rescheduling still requires the private management route. No email/SMS notification or payment is added; email verification remains off under its existing configuration.

Verification: extraction/validation tests, isolated local API complete/partial/taken-slot flows, session-switch rejection, actual save/retry and private cancel; TypeScript, build, targeted lint and browser EN/ZH review. No production test booking or paid AI call is required. No database migration/dependency/model change.
